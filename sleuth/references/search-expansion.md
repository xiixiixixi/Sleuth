# Search Expansion 搜索拓宽

**前置条件**：Scout 阶段已完成。用 Scout 发现的实际实体、来源、矛盾信号填写本清单，禁止凭想象填写。

搜索前先从六个方向想一遍。不是技巧百科，是盲区检查清单。

## 1. Entity 实体扩展

目标对象可能不只有一个名字。查清身份映射再搜，否则大面积漏结果。

- 例：Shulex / 数里 / VOC AI / voc.ai —— 同一产品线多个品牌域名
- 例：公司名 ≠ 产品名 ≠ 域名 ≠ 法人主体（尤其跨境公司）
- 例：创始人、母公司、子公司——换个主体可能完全不同的信息

> 最容易漏：只用了用户给的词搜，没做身份映射。

## 2. Question 问题扩展

用户问 A，但回答 A 之前可能必须先回答 B/C/D。

- 例：问"产品怎么样"→ 需同时查定位、客户、价格、限制、用户反馈
- 例：问"能不能用"→ 需查兼容性、许可协议、技术门槛、替代方案

> 最容易漏：直接回答表面问题，没有拆出隐藏子问题。

## 3. Source 来源扩展

只查一类来源 = 单一视角。

- 例：官方（官网/文档） vs 用户（评论/社区） vs 第三方（媒体/分析） vs 监管（工商/法院）

> 最容易漏：只查官网和前几条搜索结果，忽略社区、issue、投诉平台。

## 4. Perspective 视角扩展

同一事实，不同利益相关方看到的完全不同。

- 例：官方说"简单易用" vs 用户说"配置复杂"——哪边是真？
- 例：投资人看到增长故事，采购方看到总拥有成本，开发者看到 API 质量

> 最容易漏：只从官方或搜索摘要获取信息，没有交叉验证。

## 5. Contradiction 反证扩展 ← 重点

**模型最容易跳过的维度。只找正面材料会让结论虚高。**

- 例：搜 "productX complaint / negative / limitation / lawsuit"
- 例：搜 "productX vs alternative"——替代方案的存在本身就是反证
- 例：搜 "productX deprecated / shutdown / pricing controversy"
- 例：正面评价是否来自官方或付费渠道——软文不等于口碑

> 最容易漏：整轮调研没有任何负面搜索词。Research Loop 必须至少包含一次反证搜索。

## 6. Freshness 时效扩展

融资、价格、团队、产品能力、版本号都可能已经变化。

- 例：官网写着"最新"，但博客停更两年——可能不再维护
- 例：融资信息引用 2022 年新闻——需确认是否有更新轮次

> 最容易漏：引用旧信息时不检查是否有更新，尤其公司、价格、版本类。

搜索前用此格式快速记录（只写能改变搜索方向的，必须基于 Scout 实证）：

Expansion:
- Entities: [Scout 中发现的实际别名/关联实体]
- Hidden questions: [从搜索结果标题中推断的子问题]
- Source types: [Scout 中发现有内容的平台 + 未覆盖的平台]
- Perspectives: [搜索结果中出现的不同立场]
- Contradictions: [Scout 中发现的矛盾信号]
- Freshness: [Scout 中观察到的最新/最旧结果日期]
