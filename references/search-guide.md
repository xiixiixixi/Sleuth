# 搜索方法论

主 Agent 和子 Agent 共用同一套搜索判断。本文只回答一件事：**怎么在最少仪式下，找到足够可信的证据。**

## 七个判断动作

```text
目标 → 来源拓扑 → 观察 → 怀疑 → 换路 → 证据 → 停止
```

### 目标

先写清：

- 你要证明什么、找到什么、交付什么。
- 什么叫 enough。
- 哪些事实必须回到原始来源。

没有目标，搜索词会越搜越散。

### 来源拓扑

先问“这个事实通常存在于哪类来源”，再问“该搜什么词”。

常见来源拓扑：

| 信息类型 | 常见高价值来源 |
|----------|----------------|
| 公司基本面 | 官网 About、官方新闻、LinkedIn、投资方公告 |
| 产品能力 | Docs、API、Product 页面、Changelog、Demo |
| 定价 | Pricing、Help Center、FAQ、Sales docs |
| 客户案例 | Customers、Case Study、Marketplace、第三方测评 |
| 安全合规 | Security、Trust Center、SOC2/GDPR 页面 |
| 真实反馈 | G2、Capterra、Reddit、YouTube、社区讨论 |

## 选入口，不迷信单一路径

入口可以来自：

- WebSearch / Search APIs：发现候选页面和别名
- WebFetch / readers：快速扫静态正文
- agent-browser：验证动态页面、登录态、真实交互
- 本地历史 / 书签：找用户或组织已有入口

不要预设“所有任务都先搜索”，也不要预设“所有任务都先开浏览器”。哪个入口最可能最快产生有效证据，就先用哪个。

## 观察：每一步都要读反馈

你看到的不是“成功/失败”，而是下一步的提示：

- 搜索结果暴露了别名、子品牌、旧品牌名
- 页面暴露了更直接的 docs / pricing / security 入口
- 结果过旧，说明要加时间线或 freshness 判断
- 一个站点全是营销话术，说明要换来源类型

观察完，再决定下一步；不要机械照着原计划走。

## 怀疑：主动找自己可能错在哪

每轮都至少问几件事：

- 我现在拿到的是原始来源，还是摘要、转载、营销页？
- 这个数字有时间戳吗？有没有旧数据冲突？
- 我是不是只看了排名靠前的结果？
- 我是不是把公司名、产品名、域名混为一谈？
- 我是不是在同一条失败路径上重复尝试？

## 换路：当前路径没产出，就换来源类型

以下情况说明该换路：

- 连续两轮没有新信息
- 同一类页面互相复读
- 搜索结果都在引用同一个源
- 当前路径只剩 SEO 文、摘要或失真的 reader 输出
- 页面需要交互、展开、登录、真实状态判断，而你还在用静态 reader

常见换路方式：

- 从搜索结果切到官网、docs、pricing、security、changelog
- 从 reader 切到浏览器 DOM / eval
- 从 Google / Bing 切到 `site:`、YouTube、App Marketplace、GitHub
- 从公网搜索切到本地历史、书签、组织入口

## 证据：写结论时必须知道凭什么

关键结论至少记录：

```text
Claim → Evidence → Source → Time → Confidence → Conflict
```

最小证据记录可以很轻，不需要先上数据库：

```yaml
claim: "某产品公开价格为 $X / seat"
evidence:
  - url: "https://example.com/pricing"
    source_type: official_pricing
    observed_at: "2026-05-15"
    quote: "..."
confidence: high
conflicts: []
```

最少要求：

- 有 URL
- 能看出来源类型（official / docs / review / community / news）
- 涉及价格、融资、版本、团队等会变的事实时，要有时间线意识
- 遇到冲突，不要抹平；明确写出冲突和判断依据

### 证据层级

| 层级 | 常见来源 | 用法 |
|------|----------|------|
| **Tier 1** | 官方文档、官方博客、官方定价页、监管或权威原始文件 | 核心事实首选 |
| **Tier 2** | 行业分析、第三方深度评测、GitHub README / issues、成熟评论站 | 补强、对照、寻找反证 |
| **Tier 3** | 搜索摘要、SEO 文、未署名新闻稿、单条论坛评论 | 用于发现线索，不单独支撑核心结论 |

`Tier 3` 不能单独支撑核心结论。

## 停止：目标满足就停

可以停：

- 关键问题已答，且证据足够支持结论
- 新一轮几乎不再增加有效信息
- 剩余缺口不影响用户决策，且已明确披露

不能停：

- 关键结论只有单一脆弱来源
- 存在明显冲突但还没说明
- 重要数字没有时间或来源
- 你只是“流程做完了”，但问题还没真正回答

## 常见战术

### 1. 实体扩展

- 公司名 ≠ 产品名 ≠ 域名 ≠ 法人主体
- 中英文名、旧品牌名、母子公司关系都可能影响检索结果

### 2. 反证搜索

不要只搜正面材料。常见反证入口：

- `complaint`
- `limitation`
- `vs alternative`
- `lawsuit`
- `shutdown`
- `pricing controversy`

### 3. 站内深挖

找到高价值站点后优先深挖：

- docs
- pricing
- help / faq
- changelog
- security
- customers / case studies

### 4. 视频与演示

创始人访谈、产品演示、用户教程常在视频里。适合：

- 用搜索引擎找 YouTube 结果
- 或直接在 YouTube 站内搜

找到视频后，按 `tool-guide.md` 特殊内容类型处理字幕或转录。

## 遇到障碍时

| 障碍 | 处理 |
|------|------|
| 登录弹窗 | 先判断是否还能读到所需信息；不行就请用户登录 |
| 付费墙 | 只使用可见内容，找公开替代来源，不绕过 |
| CAPTCHA / anti-bot | 暂停该路径，换来源类型或换入口 |
| 429 / 限流 | 降低频率、换站点、换方法 |
| 页面超时 / 空白 | 改等待策略，或切到浏览器观察真实状态 |

遇到障碍时，记住：**失败是反馈，不是命令你原地重试。**
