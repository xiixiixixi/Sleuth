# 审查清单

本文档给独立审查者使用。审查的目标不是让研究“过门”，而是判断：**当前结论是否足够可信，是否还有关键缺口没有披露。**

## 输入

审查者通过 Read 获取：

- 主 Agent 提供的目标、关键问题、enough 条件
- 已有交付文件或研究摘要
- 必要时，主 Agent 标出的高风险结论或冲突点

## 先判断：这个任务真的需要独立审查吗

独立审查更有价值的情况：

- 结论会影响重要决策
- 来源多、范围大、冲突多
- 主 Agent 已经投入很多搜索成本，容易舍不得推翻自己
- 涉及价格、融资、客户、团队、版本、合规等易过时事实

如果任务很轻，审查可以简化成主 Agent 自检，不要把“必须审查”变成形式主义。

## 审查重点

| 检查项 | 要问什么 |
|--------|----------|
| **目标覆盖** | 用户真正要解决的问题是否已经答到位？ |
| **来源强度** | 核心结论是否过度依赖单一来源、低级来源或营销页？ |
| **一手验证** | 价格、版本、融资、政策等关键事实是否回到了原始来源？ |
| **冲突处理** | 是否明确写出了冲突信息，而不是强行抹平？ |
| **时效性** | 是否存在旧数据冒充新结论？ |
| **视角覆盖** | 是否只用了官方视角，漏了用户、第三方或反证？ |
| **冗余与饱和** | 是否有明显重复材料，或继续搜索已无实际增量？ |
| **披露质量** | 未确认内容、缺口、推断是否被清楚标识？ |

## 输出格式

```text
coverage:
  - 已答问题
  - 未答问题

weak_claims:
  - 证据脆弱、单一来源或明显过时的结论

missing_perspectives:
  - 缺失的来源类型或立场

red_flags:
  - critical / warning 级风险

conflicts:
  - 已发现但尚未解释清楚的冲突

is_enough:
  - true / false

next_actions:
  - 只列真正需要补的动作，不列仪式性动作
```

## 什么时候判 `is_enough=false`

- 关键问题仍未回答
- 核心结论没有可追溯来源 URL
- 关键数字只依赖单一脆弱来源
- 明显冲突未说明
- 报告把推断写成了事实

## 什么时候可以判 `is_enough=true`

- 用户目标已经被回答
- 关键结论能回到来源
- 冲突被解释或清楚披露
- 剩余缺口不影响核心判断，且已明确说明

## 对补查的要求

如果需要补查：

- 只补关键缺口，不重做整份研究
- 任务描述要具体到“补什么证据、为什么重要”
- 如果缺口本身不可得，就要求主 Agent 在最终报告里披露，而不是继续装作能搜出来
