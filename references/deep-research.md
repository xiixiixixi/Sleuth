# 深度研究工作流

什么时候读这份：**单 agent 多轮深度研究**。用户要的是完整报告、多源交叉、覆盖充分——不是一两个搜索就能答完的。

简单查询看 `search-guide.md` 就够，不要把所有任务都升级到 deep research。

## 何时进入深度研究

进入：
- 用户明确说"深度"、"完整报告"、"全面对比"
- 问题涉及多个独立子主题（对比 N 个产品、调研某领域全貌）
- 单次搜索后发现问题比预想复杂（出现冲突、需要时间线、需要多视角）

不进入：
- 1-2 次搜索能答完的事实查询
- 用户只是要个快速答案
- 问题边界清晰、单一来源即可解决

判断标准：**问题是"开放式的、需要拼图的"，还是"封闭式的、有标准答案的"**。前者进 deep research，后者走快速验证。

## 5 阶段工作流

```
澄清 → 规划 → 研究（迭代）→ 压缩 → 合成
```

### 阶段 1：澄清（Clarify）

**目标：确保你真的理解用户问什么。**

写下来：
- 用自己的话复述用户的问题（一句话）
- 列出已知条件（用户给过的信息）
- 列出未知的、需要去查的维度
- 什么叫"答完了"——用户期待的交付形式（对比表？时间线？完整报告？）

**关键判断**：用户的问题里有歧义吗？有未说明但必要的维度吗？有的话**反问一次**——但只反问一次，不要反复打断。

参考 langchain open_deep_research 的 `clarify_with_user_instructions`：评估是否需要澄清，**如果对话历史里已经问过一次，几乎不要问第二次**。

### 阶段 2：规划（Plan）

**目标：把大问题拆成可独立研究的子问题。**

输出一份 plan：
```
研究主题：<一句话>

子问题：
1. <子问题 1> —— 来源类型：<官方/学术/新闻/...>
2. <子问题 2> —— 来源类型：<...>
3. ...

执行顺序：
- 并行：<列出可同时查的>
- 串行：<列出依赖关系的>
```

**拆解原则**：
- 子问题之间**尽量独立**（一个的答案不影响另一个）
- 每个子问题**单一目标**（"查 X 的定价"而不是"查 X 的定价和融资和团队"）
- 子问题数量 = 问题的复杂度，不要为拆而拆。简单对比 2 个东西可能就 2 个子问题；全面调研一个领域可能 5-8 个

**反例**：把同一个事实从不同角度反复拆（"X 的定价"、"X 的价格"、"X 多少钱"）——这是假并行。

### 阶段 3：研究（Research Loop）

**目标：每个子问题拿到足够可信的证据。**

这是核心循环。每个子问题独立走：

```
搜 → 读页面 → 反思 → 决定下一步
 ↑                          ↓
 └──────────────────────────┘
```

**搜**（按 `search-guide.md`）：
- 短查询起步（1-6 词）
- 先 broad 再 narrow
- 多语言用户问题：双语 query

**读页面**：
- WebFetch / reader 拿静态正文（快）
- 关键事实回原始来源用浏览器验证（一手核验）
- **reader 是线索，不是证据**——核心结论必须回原始来源

**反思**（每轮必做）：
- 拿到的是原始来源还是聚合？
- 还缺什么？（gap analysis）
- 最近 2 次搜索返回的是不是类似信息？
- 同一事实有冲突吗？

**决定下一步**：
- 还缺东西 → 改写 query 再搜（按 `search-guide.md` 的查询改写规则）
- 关键事实不确定 → 升级到浏览器一手验证
- 已经够了 → 进入下一子问题或合成阶段
- 同一路径反复失败 → 换路（换来源类型、换工具、换角度）

**中间记录**：每轮搜完写下：
```
findings:
  - <已验证事实 + URL>
  - <已验证事实 + URL>
gaps:
  - <没取得的内容>
red_flags:
  - <可疑信息>
```

这是 Perplexity Deep Research 的 scratchpad 模式。所有子问题的中间记录汇总起来就是合成阶段的输入。

### 阶段 4：压缩（Compress）

**目标：把研究阶段的原始材料整理成合成阶段可用的形式。**

具体动作：
- **去重**：3 个源说同一件事 → 合成一句"3 个源都说 X"，列出 3 个 URL
- **去无关**：明显跑题的内容删掉
- **标记冲突**：A 源说 X，B 源说 Y → 明确列出冲突，标时间戳，给判断依据
- **按可信度分层**：T1（官方原始）/ T2（第三方深度）/ T3（聚合摘要）

**关键纪律**（来自 langchain open_deep_research `compress_research_system_prompt`）：
> "All relevant information should be repeated and rewritten verbatim, but in a cleaner format."
> "It's crucial that you don't lose any information from the raw messages."

**不要在这一步丢失信息**——压缩是去掉噪音，不是丢掉证据。压缩完应该比原文短，但每个原始 URL 都还在。

### 阶段 5：合成（Synthesize）

**目标：把压缩后的证据变成给用户的最终报告。**

**报告结构**（按问题类型灵活选择）：

| 问题类型 | 推荐结构 |
|---|---|
| 对比类（A vs B） | 背景 → A 概览 → B 概览 → 对比表 → 结论 |
| 清单类（"列出 X"） | 直接列表，每项一段，不需要 intro/outro |
| 调研类（"全面了解 X"） | 概览 → 关键维度 1 → 关键维度 2 → ... → 结论 |
| 时间线类 | 按时间排序，每事件一段 |
| 单一问题 | 直接答案 + 支撑证据（最简结构） |

**写作纪律**：
- **每个核心结论内联来源 URL**：`[结论](https://来源URL)`
- 单源最多 1 句直引，不超过 15 词，默认 paraphrase
- 区分 5 级可信度：已验证事实 / 高置信推断 / 未确认线索 / 冲突信息 / 覆盖缺口
- 不要自指（"作为研究员我..."）—— 直接写报告，不要元评论
- 用用户问题的语言写（用户中文问，报告中文写）

**末尾**：
- Sources 部分列出所有引用 URL
- 如果有覆盖缺口，明确写出"以下内容未取得"，列出 blindspots

## 何时停止研究（判断标准，不设数字 cap）

**可以停**：
- 每个子问题都有至少 1 个 T1/T2 来源支撑
- 核心事实之间没有未解决的冲突
- 最近 2 轮搜索没产生新信息
- 剩余缺口不影响用户的核心决策

**不能停**：
- 关键结论只有单一脆弱来源（特别是 T3 聚合摘要）
- 存在明显冲突但还没说明
- 重要数字没有时间戳或来源
- 你只是"流程做完了"，但用户的问题还没真正回答

**判断哲学**：你停不停，看的是"用户能不能拿这个报告做决策"，不是"我搜了几轮"。如果再加一轮搜索不会改变用户的决策，就停。如果会改变，继续。

## 反模式（不要这样做）

- **永远在搜，不进入合成**——搜得多不等于答得好。研究阶段的目的是支撑合成，不是凑数。
- **每轮都换完全不同的方向**——没有积累，每轮都从零开始。应该有积累，每轮基于上一轮的 gap。
- **只搜正面材料**——核心结论要经得起反证。对每个关键事实主动搜反证（complaint / lawsuit / limitation / vs alternative）。
- **抹平冲突**——冲突是信息，不是噪音。明确写出"A 源说 X，B 源说 Y，本报告采信 X 因为..."。
- **抄源结构**——不要用 bullet list 重现原文章结构（版权问题 + 没加价值）。重新组织。

## 报告交付

按 SKILL.md 的交付段：
- 用户指定了输出形式 → 严格按用户要求
- 简单问题 → 内联回复 + URL
- 复杂问题 → Markdown 报告写到 cwd 或 `~/.sleuth/output/YYYY-MM-DD/`
- 多子 agent 并行 → 看下一节，或读 `multi-agent.md`
