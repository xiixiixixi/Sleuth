# Search Expansion 搜索拓宽

这不是强制流程，也不是每次都要逐项打勾的表格。它只是一个提醒：当你发现搜索陷入重复、偏见或盲区时，可以从下面几个方向检查自己漏了什么。

## 1. Entity 实体扩展

目标对象可能有多个名字。

- 公司名 ≠ 产品名 ≠ 域名 ≠ 法人主体
- 可能存在中英文名、旧品牌名、子品牌名、母子公司关系
- 创始人或核心产品名有时比公司名更容易找到一手信息

最容易漏：只用了用户给的词搜，没做身份映射。

## 2. Question 问题扩展

用户问 A，答案可能依赖 B / C / D。

- 问“产品怎么样” → 可能还要看定位、客户、价格、限制、用户反馈
- 问“能不能用” → 可能还要看兼容性、许可协议、技术门槛、替代方案

最容易漏：只回答表面问题，没有拆出隐含子问题。

## 3. Source 来源扩展

只查一类来源，就只得到一种视角。

- 官方：官网 / docs / blog / pricing
- 用户：评论站 / 社区 / issue / 视频教程
- 第三方：媒体 / 分析 / 评测
- 监管或公开记录：工商 / 法院 / 监管文件 / 投资公告

最容易漏：只查官网和前几条搜索结果。

## 4. Perspective 视角扩展

同一事实，不同角色看到的很可能不同。

- 官方会强调能力和优势
- 用户会暴露使用门槛和真实成本
- 采购方会关心总拥有成本和合同模式
- 开发者会关心 API、文档和限制

最容易漏：只站在一个利益相关方的角度看问题。

## 5. Contradiction 反证扩展

这是最容易被跳过、但最有价值的一维。

可用的负向或对照入口：

- `complaint`
- `negative`
- `limitation`
- `lawsuit`
- `deprecated`
- `shutdown`
- `pricing controversy`
- `vs alternative`

最容易漏：整轮研究都没主动找过反证。

## 6. Freshness 时效扩展

融资、价格、团队、版本、功能都会变。

- 旧融资新闻可能已被新一轮覆盖
- 旧 pricing 页面可能已失效
- 官网写“latest”不代表真的最新

最容易漏：看到一个数字就写进报告，却没有时间意识。

## 什么时候拿它出来用

最适合这些时刻：

- 搜索结果开始重复
- 你怀疑自己只看到了单一来源
- 你发现实体、品牌或域名有混淆
- 你感觉“信息很多，但没有新东西”

## 建议记录格式

只记录会改变搜索方向的东西，不要为了形式把六项都写满。

```text
Expansion:
- Entities: [发现的别名 / 关联实体]
- Hidden questions: [需要新增回答的子问题]
- Source types: [已覆盖 / 未覆盖的来源类型]
- Perspectives: [还缺哪个视角]
- Contradictions: [发现的矛盾信号]
- Freshness: [关键页面或数据的日期线索]
```
