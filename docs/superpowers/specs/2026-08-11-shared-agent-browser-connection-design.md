# agent-browser 共享连接与动作级排队设计

> 状态：2026-08-11 用户已确认。验收只看三件事：调用者不互相抢浏览器、子 Agent 不因浏览器而整队串行、任何调用者都不能读错或操作错页面。

## 一句话目标

所有调用者共享 `agent-browser` 默认后台服务与用户日常 Chrome 的一条连接；搜索、网页读取和分析继续并行，只有一次真实浏览器命令在执行前短暂排队。协调脚本必须自动选回调用者自己的标签页，并把命令和最终页面核对放在同一个批次里。

## 范围

本次只处理：

1. 默认 `agent-browser` 后台服务与用户日常 Chrome 的连接复用。
2. 多个调用者同时使用该默认后台服务时的一次操作级协调。
3. 搜索子 Agent 的命令入口和防止读错页面的验证。

以下事项不在范围内：

- 不修改或约束其他浏览器工具、插件、Playwright 或其他 Agent 产品。
- 不启动、关闭、重启或替换用户的 Chrome。
- 不创建测试浏览器、独立用户目录或复制登录数据。
- 不承诺 Chrome 重启后永久免授权；新的控制连接仍可能需要用户允许一次。

## 核心原则

### 1. 一条持久连接

- 只使用默认后台服务和 `~/.agent-browser/default.sock`。
- 禁止使用 `--session` 或 `--namespace` 创建额外后台服务。
- 所有共享命令显式使用 `--idle-timeout 0`。在当前 `agent-browser` 中，`0` 表示关闭闲置退出；这不会关闭或重启用户 Chrome。
- Chrome 没退出且连接仍健康时，后续调用直接复用；禁止为了“保险”建立第二条连接。
- 禁止使用裸 `agent-browser close` 或 `close --all` 结束用户 Chrome。

### 2. 子 Agent 始终并行

- WebSearch、网页读取、证据整理、写 raw 和分析始终并行。
- 子 Agent 不提前申请浏览器，也不持有跨命令的租约。
- 只有调用 `shared-browser.mjs exec` 的那几秒进入短队列；命令结束或失败后自动释放。
- 一个 Agent 等待浏览器时，其他 Agent 的非浏览器工作不受影响。

### 3. 页面身份由脚本保证

同一个 Chrome 只有一个活动标签。为了避免 A 选好页面后被 B 切走，正常命令必须在一次 `agent-browser batch --bail --json` 中依次完成：

```json
[
  ["tab", "<调用者自己的标签>"],
  ["<浏览器命令>", "<参数>"],
  ["tab", "<调用者自己的标签>"],
  ["get", "url"],
  ["get", "title"]
]
```

- 标签不存在时，协调脚本在同一个短锁内创建并标记它，然后执行上面的批次。
- 命令结束后必须再次选择调用者标签，再读取 URL 和标题；即使网页点击意外打开了新标签，也不能把新标签误当成调用者页面。
- URL 和标题是本次操作结果的一部分，调用者必须据此判断是否仍在目标页面。
- 禁止 `--new-tab` 和 `window.open(...)`。需要跟随新窗口链接时，先读取 `href`，再在调用者自己的标签中执行 `open <url>`。
- 共享模式禁止跨命令复用 `@eN` 元素引用。`agent-browser` 的元素引用属于生成快照时的活动标签；其他调用者切换页面后继续用旧引用，存在误操作风险。交互必须使用稳定选择器、`find` 单命令，或重新观察后执行不依赖旧引用的操作。
- 关闭标签属于特殊命令：只允许关闭当前调用者自己声明的标签；关闭后不再读取 URL 和标题。

## 单一执行入口

搜索子 Agent 只使用：

```bash
SLEUTH_CDP_PORT=<同次-full-检查端口> \
SLEUTH_CDP_WS='<同次-full-检查完整地址>' \
node scripts/shared-browser.mjs exec \
  --owner <task-agent-id> \
  --tab <task-agent-id> \
  -- <agent-browser-command>
```

另有只读诊断入口：

```bash
node scripts/shared-browser.mjs status --json
```

子 Agent 不执行 `acquire`、`release` 或 `run`。协调脚本内部负责等待、选择页面、执行、核验和释放，因此不会发生忘记释放导致后续任务全部堵住。

协调数据放在 `~/.sleuth/shared-browser-control/`，只包含短锁的 owner、进程号和开始时间；禁止保存 cookie、页面正文或登录数据。

## 连接检查与恢复

### 当前连接可用

每次 `exec` 都必须带同次 full 检查核验过的 `SLEUTH_CDP_PORT` 和完整 `SLEUTH_CDP_WS`。协调脚本在短锁内把完整地址传给默认后台服务：

- 默认后台服务仍连接当前 Chrome 时，命令直接复用原连接。
- 默认后台服务尚未运行时，第一条命令建立它与当前 Chrome 的连接。
- Chrome 要求授权时，只会有取得短锁的调用者发起连接；其他浏览器调用继续排队，不建立第二条连接。

### 当前连接不可用

- Chrome 重启、完整地址失效、身份不合格或命令无法连接时，返回 `BROWSER_CONTROL_REQUIRED`。
- 主 Agent 必须重新运行 full 检查取得新的完整地址；禁止猜测、拼接或复用旧地址。
- 协调脚本绝不自行启动、关闭或重启 Chrome，也不运行 `agent-browser install`。
- 本期不自动杀死无法确认身份的旧后台进程。连接恢复需要清理时必须只处理已确认的 `agent-browser` 默认后台服务，且不能关闭用户 Chrome。

## 短锁规则

- 锁只从一次 `exec` 真正准备切换标签前开始，到命令完成、核验完成或失败时结束。
- 锁使用文件系统原子创建，两个进程不能同时进入浏览器批次。
- `try/finally` 必须保证正常完成、命令失败和连接失败都会删除自己创建的锁。
- 协调器被强制终止时，底层浏览器命令可能仍在运行。此时残留锁必须保留并返回 `BROWSER_BUSY`，绝不根据外层进程消失自动强拆，也绝不让下一条命令冒险进入。
- `status` 只读报告当前是否有命令正在执行，不取得锁，也不读取网页。

## Sleuth 接入

### 主流程

- 搜索 Agent 仍按原规则最多并行 5 个。
- 主 Agent 可以把同次 full 检查的端口和完整地址同时注入多个搜索任务。
- 搜索 Agent 只有在轻量工具失败、确实需要浏览器的那一刻才调用 wrapper（包装脚本）。
- 多个 Agent 同时到达浏览器步骤时，各自的单次命令短暂排队；任一命令结束后下一条立即执行，不等待前一个 Agent 完成研究任务。

### 搜索提示

`spawn-subagent.mjs` 必须把完整地址内联到 `shared-browser.mjs exec` 示例中，并明确：

1. 禁止直接运行 `agent-browser --cdp` 绕过协调器。
2. 禁止手动 `acquire/release`。
3. 每次调用固定使用自己的唯一 owner 和标签名；搜索 prompt 根据任务目录、轮次和 Agent 名生成短哈希身份，其他项目里同名的 Agent 也不能共用标签。
4. 轻量搜索、分析和写文件继续并行。
5. 命令输出中的最终 URL/标题必须与目标页面相符。
6. 任务结束只通过相同入口关闭自己的标签，禁止关闭用户或其他 Agent 的标签。

## 状态与错误处理

| 状态 | 行为 |
|---|---|
| 没有浏览器命令正在执行 | 当前 `exec` 立即进入短锁并运行 |
| 另一条浏览器命令正在执行 | 当前 `exec` 只等待这条命令结束；其他工作继续并行 |
| 默认后台未运行、完整地址有效 | 当前 `exec` 建立默认连接；可能要求用户允许一次 |
| 默认后台和连接健康 | 直接复用，不建立第二条连接 |
| Chrome 已重启或完整地址失效 | 返回 `BROWSER_CONTROL_REQUIRED`，重新 full 检查 |
| 当前命令失败 | 自动释放短锁；下一位仍可运行 |
| 持锁进程已消失或元数据损坏 | 标记 `stale:true` 并返回 `BROWSER_BUSY`；禁止自动强拆，避免撞上仍在运行的孤儿命令 |
| 活进程长期占用 | 返回 `BROWSER_BUSY`，禁止强抢 |

## 安全边界

- 协调脚本绝不读取、导出或复制 cookie、密码和本地存储。
- 禁止 `--profile`、`--auto-connect`、`--session`、`--namespace`、`--config`、`--new-tab` 和远程主机地址；调用底层 CLI 前必须清除会改变后台、会话、浏览器或配置来源的危险 `AGENT_BROWSER_*` 环境变量。
- 禁止裸 `close`、`close --all` 和关闭非本 owner 标签。
- 页面提交、下单、发帖、删除、改配置等状态变化继续遵守用户确认规则；进入短锁不等于取得业务操作授权。
- 其他不通过此 wrapper 的浏览器工具不受本期协调器控制；本设计只保证所有遵守 Sleuth 契约的 `agent-browser` 调用者不会互相抢页。

## 测试与完成标准

### 自动测试

1. 两个并发 `exec` 的浏览器批次绝不重叠。
2. A 的命令只能在 A 标签执行，B 的命令只能在 B 标签执行。
3. 正常完成、命令失败和连接失败后都没有残留短锁；下一条命令可立即继续。协调器被强制终止时必须保留保护锁并拒绝自动强拆。
4. 没有任务级 `acquire/release` 接口，等待不会覆盖整个 Agent 生命周期。
5. `@eN`、新标签命令、命名会话、危险环境变量、其他 CDP 地址、裸关闭和关闭其他标签均被拒绝。
6. 搜索 prompt 只使用协调器，并明确轻量工作继续并行。
7. Chrome 未就绪时产生 `BROWSER_CONTROL_REQUIRED`，禁止自起浏览器。

### 真实 Chrome 验收

1. 用两个 owner 并发提交两条导航，分别绑定两个本任务标签和两个不同页面。
2. 两条命令可以同时发起，但浏览器批次按短锁依次完成；不需要等待任一搜索 Agent 的整个任务。
3. 随后并发读取两个标签的 URL 和标题，A/B 均得到自己的页面，不能交叉。
4. 所有命令复用默认后台服务、`default.sock` 和同一条 Chrome 调试连接；不得出现命名 `.sock`。
5. 如果首次需要授权，用户允许一次后，紧接的后续命令不再弹；Chrome 或默认后台退出后的新连接仍可能再次弹。
6. 只关闭本次新建的 A/B 标签，保留用户原有标签页。
7. 按 `docs/TESTING.md` 运行全部自动测试、文档检查和真实浏览器环境检查。

## 最终成功定义

完成不以“代码已改”或“命令能运行”为准，必须同时满足：

- 不互相打仗：两个 `agent-browser` 调用不能同时改变活动标签。
- 不是整队串行：只有单条浏览器命令短暂排队，所有非浏览器工作继续并行。
- 不读错页面：每条命令都在自己的标签执行，并返回同批次核验的 URL 和标题。
- Chrome 未退出且连接健康时，默认后台连接持续复用。
- 自动测试和真实 Chrome 双标签并发验收全部通过。
