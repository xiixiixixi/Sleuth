# agent-browser 后台连接生命周期设计

## 问题

`agent-browser` 会为每个会话启动一个常驻后台服务。连接用户现有 Chrome 时，默认闲置退出规则不生效，因此旧研究和测试留下的后台服务会长期存在。Chrome 会把新的后台服务视为新的外部控制请求，导致“要允许远程调试吗？”反复出现。

本机排查时发现 11 个残留后台服务，分别来自旧探测、批次测试和研究任务；停止这些服务后，弹窗消失，Chrome 与用户标签页保持不变。

## 目标

- Sleuth 的浏览器兜底只复用 `agent-browser` 默认会话，不为搜索角色另建会话或命名空间。
- 所有连接用户 Chrome 的命令显式设置 1 小时闲置退出，避免后台服务遗留数天。
- 闲置退出只断开控制服务，绝不关闭用户的 Chrome 或已有标签页。
- Chrome 重启或后台服务已经退出后的第一次连接仍可能出现一次官方授权弹窗；这是浏览器安全确认，不承诺消除。

## 方案

统一命令前缀为：

```bash
agent-browser --cdp <port> --idle-timeout 1h <command>
```

同时保留以下硬规则：

- 禁止使用 `--session` 或 `--namespace` 为同一个 Chrome 建立额外后台服务。
- 浏览器操作继续串行，同一时刻只把端口交给一个搜索角色。
- 禁止使用 `agent-browser close` 或 `close --all` 结束用户现有 Chrome；由显式闲置时间让后台服务自行断开。
- 不自动强杀未知的 `agent-browser` 进程，避免打断其他正在运行的任务。历史残留只在确认来源后人工清理。

## 修改范围

- `SKILL.md`：把固定闲置时间加入浏览器兜底硬规则。
- `references/tool-guide.md`：所有示例和命令说明统一带 `--idle-timeout 1h`。
- `scripts/spawn-subagent.mjs`：生成给搜索角色的提示时给出完整固定前缀，并禁止另建会话或命名空间。
- 现有 `node:test` 测试：先增加会失败的断言，再完成最小修改。

## 验证

1. 单独运行相关测试，确认修改前因缺少闲置参数而失败，修改后通过。
2. 运行全部自动测试和文档检查，确保其他研究流程不受影响。
3. 真实 Chrome 验证只建立一个默认后台服务；连续命令复用同一进程，不新增会话。真实连接可能触发一次 Chrome 官方授权，需要在测试当时由用户确认。

## 不做的事

- 不关闭、重启或替换用户 Chrome。
- 不恢复 `~/.sleuth/chrome-live` 独立浏览器方案。
- 不试图绕过 Chrome 的官方安全确认。
- 不引入常驻系统服务或新的浏览器配置目录。
